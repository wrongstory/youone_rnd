### 상위 원문 반영 결과

- 운영 규정은 연구성과·연구노트·시설 등 유무형 결과물의 회사 귀속을 원칙으로 하되 법령·협약·계약 예외를 둔다.
- 모든 활성 내부사용자는 일반 프로젝트를 생성할 수 있다. 일반 Project 생애주기와 정식 연구과제 지정은 분리하며, 승격 신청의 봉인 버전에 대한 연구소장 검토·동의로 승격을 완료한다. 최신 사용자 결정에 따라 선임·대표 단계는 두지 않는다.
- 연구장비 외부 반출 및 기술정보 외부 반출에는 연구소장 승인이 필요하다. L1 분류도 자동 외부반출 권한이 아니다.
- 안전관리규정은 안전관리자 지정, 월 1회 정기점검, 팀 주 1회 자체점검, 반기 1회 정기교육, 연 1회 비상대피훈련, 사고조사 48시간, 관련 기록 최소 3년을 요구한다.
- 일반문서 5년 보존정책이 안전기록 최소 3년보다 길므로 안전기록 기본 보존은 최소 5년으로 설계하되, 관련 법령이 더 길면 그 기간을 따른다.
- 연구수당 규정은 대상자격, 직책/성과 수당, S/A/B/C 기여도평가와 제한사유를 정하지만, 성과수당 지급주기 문구와 세무 문구에 내부 불일치/검증 필요사항이 있다.

## 7. 감사 결론

- 00~15와 상위 사내규정 3종 원문을 모두 확인했고, 최신 사용자 결정과 2026-08-21 공식 법령 기준을 반영했다. 기술스택과 `P0-SCOPE-V1.0`은 확정됐지만 Development Gate의 명시적 착수 승인이 없어 구현은 시작하지 않는다.
- 핵심 업무를 JSON 문서 하나나 자유 문자열 상태 하나로 저장하면 추적성·권한·감사가 깨진다. 도메인 엔티티와 상태전이를 구조화해야 한다.
- 기술스택은 초기 Supabase 사용을 존중하되, UI의 Supabase 직접 호출을 금지하고 Application Service/Repository/Adapter 및 Postgres RLS를 함께 사용한다.
- 다음 단계는 사용자 리뷰와 Gate 승인이다. 승인 전 제품 코드·스캐폴딩·DB migration을 시작하지 않는다.
