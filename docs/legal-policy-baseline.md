# 법령 기반 초기 운영정책

- 기준일: 2026-08-21 (Asia/Seoul)
- 성격: 회사가 시스템에 적용할 **버전형 내부 기본정책**. 개별 계약, 정부과제 협약, 강행법규가 다르면 해당 기준이 우선한다.
- 적용 원칙: 아래 수치는 민간계약의 법정 고정값이 아니다. 계약유형·거래당사자·하도급법 적용 여부를 확인한 뒤 계약별로 변경할 수 있으며, 변경 이유와 승인 이력을 남긴다.

## 1. 계약 사전 법령 체크

계약 또는 변경계약을 체결하기 전에 다음 체크를 모두 기록한다.

- [ ] 당사자의 기업규모·업종·거래구조를 기준으로 하도급법 적용 여부를 판정했다.
- [ ] 작업 시작 전에 목적물, 납기, 장소, 검사방법, 대금, 지급방법 등 위탁내용을 전자문서로 확정했다.
- [ ] 추가·변경위탁도 작업 시작 전에 변경서면과 변경금액·일정을 확정했다.
- [ ] 주요 원재료·에너지 연동 대상과 예외사유를 검토했다.
- [ ] 검사기준은 객관적이고 공정하게 합의했으며, 수령일과 검사결과 서면통지 기한을 추적한다.
- [ ] 기술자료 요구가 필요한 경우 목적·범위·사용기간·보유자·반환/폐기·손해배상 조건을 특정하고 비밀유지계약을 체결했다.
- [ ] 지식재산권, 제3자 권리침해, 개인정보, 수출통제, 안전, 재위탁 조건을 확인했다.
- [ ] 보증, 지체상금, 책임한도, 하자기간, 검수·지급률을 계약별 명시값으로 확정했다.
- [ ] 법령 검토일, 적용 법령 버전, 검토자, 예외와 승인자를 기록했다.

하도급법 적용 거래에서는 목적물 수령 후 검사결과를 원칙적으로 10일 이내 서면 통지하도록 알림을 둔다. 정당한 사유 없이 기간 내 통지하지 않으면 합격으로 간주될 수 있으므로, 시스템은 미통지를 자동 불합격이나 지급보류로 처리하지 않는다.

## 2. 계약 수치 초기 프리셋

`POL-CONTRACT-BASELINE-V1`은 신규 계약 작성 시 제안되는 내부 프리셋이다. 사용자가 확정하기 전에는 계약조건이 아니며, 계약 승인본에는 실제 선택값과 근거가 스냅샷으로 저장된다.

| 항목 | 내부 초기 프리셋 | 적용·변경 규칙 |
|---|---:|---|
| 계약이행보증 | 계약금액의 10% | 국가계약 기준을 비교근거로 채택한 내부값. 거래규모·신용·선급금에 따라 승인 후 변경 |
| 선급금보증 | 미정산 선급금 100%와 약정이자 상당액 | 선급금이 있을 때만 적용 |
| 하자보수보증 | 제조 3%, 용역·수리·가공 2% | 공공계약 기준을 비교근거로 한 내부값. 소프트웨어·기술용역의 실질에 따라 선택 |
| 지체상금/일 | 통합 설계·제조 0.05%, 물품 제조·구매 0.075%, 용역·수리·가공 0.125% | 국가계약 시행규칙 수치를 비교 프리셋으로 사용. 민간계약 법정률로 표시하지 않음 |
| 지체상금 누적 상한 | 계약금액의 10% | 민법상 과다한 손해배상예정액 감액 가능성을 고려한 내부 위험한도. 실제 손해·계약유형에 따라 변경 |
| 일반 하자담보기간 | 최종합격일 또는 인도일 중 늦은 날부터 12개월 | 안전·핵심부품·장기내구 요구는 24개월 이상 별도 설정 가능 |
| 손해배상 책임한도 | 총 계약금액 100% | 고의·중과실, 비밀유지/기술자료 침해, 지식재산권 침해, 인명·신체손해, 법상 제한 불가 책임은 한도 예외 후보로 반드시 검토 |
| 보험·추가 법령검토 | L3/L4 취급, 안전중요 작업, 개인정보 처리, 국외이전, 계약금액 5천만원 이상 | 하나라도 해당하면 강화 검토 체크리스트와 대표 결재를 추가 |

국가·지방계약 법령의 수치는 공공조달 주체에 직접 적용되는 기준이다. 이 회사의 민간 외주계약에는 **비교 가능한 내부 프리셋**으로만 사용한다. 민법 제398조에 따라 손해배상액을 예정할 수 있으나 부당하게 과다하면 감액될 수 있으므로, 지체상금과 별도 손해배상의 중복 범위를 계약문서에서 명확히 한다.

## 3. 검수 달성도와 차등지급

정책 ID는 `POL-ACCEPTANCE-PAYMENT-V1`이다.

### 체크리스트 구조

- 검수기준 버전은 계약·마일스톤·산출물 버전에 고정한다.
- 각 항목은 `weight_percent`, `critical`, `required_evidence`, `measurement_rule`, `pass_rule`을 가진다.
- 전체 가중치 합계는 100이어야 한다.
- 항목 달성률은 0~100%이고, 항목 점수는 `가중치 × 항목 달성률`이다.
- 전체 달성도는 항목 점수의 합이며 소수점 처리 규칙도 정책 버전에 저장한다.

### 초기 판정·지급 프리셋

| 달성도 | 기본 판정 | 기본 지급률 | 추가 조건 |
|---:|---|---:|---|
| 100% | `ACCEPTED` | 100% | 모든 필수 증빙과 중요항목 통과 |
| 90% 이상 100% 미만 | `CONDITIONAL_ACCEPTANCE` | 달성도와 동일 | 잔여조건, 완료기한, 보류금액을 명시 |
| 60% 이상 90% 미만 | `PARTIAL_ACCEPTANCE` | 달성도와 동일 | 독립적으로 사용 가능한 인도분과 미완료분을 구분 |
| 60% 미만 | `REJECTED` | 0% | 시정·재검수 또는 해지검토 |

중요항목 실패 시 달성도만으로 `ACCEPTED`가 될 수 없다. 중요항목 실패분이 독립적인 사용가능 부분과 분리되는 경우에만 `PARTIAL_ACCEPTANCE`와 제한 지급을 검토한다.

지급률은 계약별로 0~100% 범위에서 조정할 수 있다. 자동 계산값과 조정값을 모두 보존하고, 조정사유·조정자·근거·승인 인스턴스를 필수로 기록한다. 조정으로 지급률을 높일 때는 연구소장과 계약금액 구간에 따른 대표 결재가 필요하다. 최종 승인률로 계산한 지급가능액은 해당 지급정책 버전의 반올림 규칙과 함께 봉인하며, 보류액과 미지급 잔액은 동일한 금액 기준을 사용하고 지급가능액을 초과할 수 없다. 미지급 잔액은 시정·재검수 또는 최종정산까지 보류하며, 부분/조건부 합격이나 지급은 외주업체의 하자·전문책임을 면제하지 않는다.

## 4. 문서유형·금액·보안등급별 결재정책

정책 ID는 `POL-APPROVAL-MATRIX-V1`이다. 직위와 Role은 분리하며, 선임은 검토/합의만 하고 공식 승인권자가 아니다.

| 대상 | 조건 | 필수 결재선 |
|---|---|---|
| 일반 사내문서 | 금액 없음, L1/L2 | 작성자 → 선임 검토(선택/정책) → 연구소장 승인 |
| 프로젝트 | 일반 프로젝트 생성·운영 | 모든 활성 내부사용자 생성 가능; 프로젝트 책임자 지정 |
| 정식 연구과제 승격 | 금액 무관 | 신청자 → 연구소장 검토·동의(최종). 선임·대표 단계 없음 |
| 구매·지출 | 100만원 미만 | 작성자 → 연구소장 승인 |
| 구매·지출 | 100만원 이상 1,000만원 미만 | 작성자 → 연구소장 → 대표 `ANY_ONE` |
| 구매·지출 | 1,000만원 이상 | 작성자 → 연구소장 → 대표 `ANY_ONE`; 5,000만원 이상은 강화 법령체크 필수 |
| 외주계약/변경계약 | 금액 무관 | 계약담당 → 연구소장 → 대표 `ANY_ONE`; 5,000만원 이상 또는 강화위험은 대표 `ALL` |
| 연구수당 정책/지급결정 | 과제별 | 평가자 → 연구소장 평가 → 대표 `ANY_ONE` |
| L1/L2 기술정보 외부반출 | 등급 무관 | 연구소장 승인 |
| L3 출력·인계 | 예외적 필요 | 연구소장 승인 + 보안 인계기록 |
| L4 출력·인계 | 극히 예외적 필요 | 연구소장 + 대표 `ANY_ONE` 승인 + 보안 인계기록 |
| 기술문서 폐기 | 모든 등급 | 문서관리 검토 → 연구소장 → 대표 `ANY_ONE` |
| 안전중지 해제/중대사고 종결 | 해당 시 | 안전관리자 검증 → 연구소장; 대외신고/중대사고는 대표 참조 또는 승인 |

금액 경계는 부가세 포함 총부담액과 누적 변경계약액을 기준으로 회피 분할을 방지한다. L3/L4, 개인정보, 안전중요, 지식재산 이전, 무제한 책임, 국외이전 조건은 금액보다 우선해 강화 결재를 적용한다.

## 5. L3/L4 통제 출력·인계

외부업체에는 L3/L4 원문 파일 다운로드와 수신자 자체 출력 권한을 부여하지 않는다.

1. 승인된 정확한 문서 버전만 내부 권한자가 출력한다.
2. 매 페이지에 보안등급, 수신자/업체, 프로젝트, 사본번호, 출력자, 출력시각, `무단복제·재배포 금지` 워터마크를 넣는다.
3. `CONTROLLED_PRINT_HANDOVER` 기록에 매수, 인계자·수령자, 목적, 회수/파기예정일, 승인 인스턴스를 저장한다.
4. 수령확인 서명 또는 전자확인을 받는다.
5. 목적 종료 시 회수 또는 파기확인서를 기록한다.
6. L4는 연구소장과 대표 승인 없이는 출력 자체가 불가하다.

## 6. 연구수당 세무 초기정책

정책 ID는 `POL-ALLOWANCE-TAX-V1`이다. 세법상 비과세와 근로기준법상 임금성은 서로 다른 판정이므로 별도 필드와 근거를 유지한다.

- 과제별 `project_allowance_policy_version`이 있는 프로젝트만 수당 계산대상이 된다.
- 과제별로 수당종류, 대상자, 예산, 평가기준, 지급주기(`MONTHLY`, `QUARTERLY`, `SEMIANNUAL`, `MILESTONE`, `PROJECT_END`), 유효기간을 정한다.
- 연구활동비 성격의 월 비과세는 회사가 중소·벤처기업이고, 인정받은 기업부설연구소에서 해당 종업원이 연구에 직접 종사하며, 소득세법 시행령 요건을 충족하는 경우에만 검토한다.
- 직책명, 시스템 Role, KOITA 등록 사실만으로 비과세를 자동 확정하지 않는다.
- 동일인·동일월의 여러 과제에서 발생한 적격 연구활동비를 합산해 월 20만원 한도를 한 번만 적용하고 초과분은 과세 기본값으로 분류한다.
- 행정지원·일반관리 인력, 성과급·프로젝트 종료 보너스, 요건증빙이 불충분한 지급은 과세 기본값으로 둔다.
- 정기적·일률적 지급 여부 등 임금성 판단은 지급조건별로 별도 기록하며, 비과세 판정이 임금/통상임금 제외를 뜻하지 않는다.
- 급여 전송 전 적용 법령일, 회사 자격, 연구소 인정상태, 직접 연구종사 증빙, 월 누적액을 재검증한다.
